# Hraness Engineering

Hraness Engineering is a compact set of Agent Skills for repository understanding and disciplined engineering work. The skills divide ownership by outcome so a request has one primary route.

| Skill | Owns |
| --- | --- |
| `repository-feature-map` | A navigable map of repository domains, entry points, flows, and validation surfaces. |
| `semantic-code-analysis` | Evidence-backed explanations of how code behaves now. |
| `reconstruct-rationale` | Historical evidence for why code reached its current shape. |
| `assess-change-impact` | The blast radius and compatibility risks of a proposed or existing change. |
| `compare-approaches` | A decision-ready comparison of viable technical approaches. |
| `create-app-verifier` | A new project-local application-driving verification skill. |
| `maintain-app-verifier` | Drift correction for an existing application verifier and feature map. |
| `test-engineer` | Test strategy, reproduction, and reliable test implementation. |
| `performance-investigator` | Measurement-led diagnosis and improvement of performance. |
| `docs-maintainer` | Documentation changes grounded in current authoritative behavior. |
| `refactor-maintainer` | Behavior-preserving structural change with explicit invariants. |

These skills do not replace repository gates, CI, merge policy, host scheduling, or delivery orchestration. They use the target repository's existing commands and conventions and preserve unrelated work.
